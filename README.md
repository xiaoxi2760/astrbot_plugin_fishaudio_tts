# FishAudio TTS 音色克隆

基于 [FishAudio](https://fish.audio) API 的 AstrBot 语音合成插件，支持多音色克隆，把文字转成语音并直接以语音消息发送。

## 功能一览

- **自然触发** — 发送 `音色名说 文本`（如 `小爱说 今天天气真不错`）直接合成语音
- **LLM 语音工具** — AI 可调用 `tts_speak` 工具朗读内容，语音之外仍会附带一小段文字回复（不整段重复朗读内容）
- **主动开口** — 开启后自动在 LLM 请求前注入提示（含可用音色列表），鼓励 AI 主动用语音说话
- **多音色** — 支持任意数量音色，按行配置，长名称优先匹配
- **情感标签** — 支持 `[happy]`、`[sad]`、`[angry]` 等 8 种官方情感标签，其他标签原样透传
- **管理员开关** — 仅管理员可执行 `/tts` 开启或关闭功能（默认开启）
- **频率限制** — 可配置调用间隔，管理员豁免，`0` 表示不限制
- **HTTP 代理** — 支持通过代理访问 API
- **向下兼容** — 兼容旧版 `reference_id` 配置

## 安装

1. 将本目录放入 AstrBot 插件目录（默认 `data/plugins`）：

   ```
   astrbot
   ├── data
   │   └── plugins
   │       └── astrbot_plugin_fishaudio_tts/   # 本插件
   ```

2. 重启 AstrBot，或在 WebUI 中重新加载插件
3. 进入插件管理页，填入配置并启用

## 配置

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `api_key` | FishAudio API Key（必填） | — |
| `api_base_url` | API 地址，自部署时可修改 | `https://api.fish.audio` |
| `model` | TTS 模型 | `s2.1-pro-free` |
| `proxy` | HTTP 代理，格式 `http://ip:port`，留空不使用 | — |
| `voice_names` | 音色名称，一行一个 | `默认音色` |
| `voice_ids` | 音色 ID，一行一个（与名称一一对应） | — |
| `rate_limit_seconds` | 用户调用间隔（秒），`0` 不限制 | `5` |

### 获取 API Key

在 https://fish.audio/app/api-keys 注册并创建一个 API Key，填入 `api_key`。

### 获取音色 ID

在 https://fish.audio/models 选择音色并复制其 ID，填入 `voice_ids`。

### 配置示例

```
voice_names:        voice_ids:
默认音色            音色ID0
小爱                音色ID1
沉稳男声            音色ID2
```

> 名称与 ID 按行一一对应，行数不一致时按较少一方截断。`voice_names` 与 `voice_ids` 均为空时，自动回退读取旧版 `reference_id`。

### 可用模型

| 模型 | 说明 |
|------|------|
| `s2.1-pro-free` | 免费版（默认） |
| `s2.1-pro` | 收费版 |
| `s2-pro` | 上一代收费版 |
| `s1` | 基础版 |

## 使用

### 1. 管理员开关

发送 `/tts` 开启（回复「想听我说什么呀？」），再次发送关闭（回复「喔，那我闭嘴咯。」）。开关状态重启后默认开启。

### 2. 音色名触发

```
小爱说 今天天气真不错
小爱说 [happy]今天是个好日子
```

匹配规则：

- 音色名 +「说」+ 空格 + 文本，音色名必须是配置中已存在的名称
- 多个音色时，长名称优先匹配，避免「爱」和「小爱」误匹配
- 触发命中后会终止该消息的后续处理，其他插件和 LLM 不再处理

合成失败（未启用、未配置 Key/音色、触发频率限制或 API 异常）时回复：

```
小爱说累啦，让她休息一会儿吧
```

### 3. LLM 语音工具 `tts_speak`

管理员开启 TTS 后，AI 可调用 `tts_speak` 工具朗读内容：

```text
text:        要朗读的完整内容（必填，只作为音频发送，不重复输出为文字）
voice_name:  可选，用户明确指定的已配置音色名称
emotion:     可选，happy、sad、angry、whisper、excited、neutral、fearful、surprised
```

行为说明：

- 未指定 `voice_name` 时使用配置列表中的第一个音色；指定的音色不存在时提示合成失败
- 指定 `emotion` 后自动在文本前添加对应标签（如 `[happy]文本`），已带标签不重复添加；未列出的情绪标签也会原样透传，不会导致调用失败
- 用户要求朗读、用声音回复或角色扮演时，AI 应主动调用；普通问答不需要每次调用
- 调用 `tts_speak` 后 AI 仍会输出一小段文字回复（语气词、旁白或简短回应），不会只发语音不说话；只是不会把 `text` 内容整段重复成文字
- 语音会附带 🎤 标记一起发送，避免消息链只有引用时被框架拦截

## 情感标签

标签需放在文本最前面，8 种官方常用标签：

| 标签 | 效果 |
|------|------|
| `[happy]` | 开心、愉悦 |
| `[sad]` | 悲伤、难过 |
| `[angry]` | 生气、愤怒 |
| `[whisper]` | 低语、悄悄话 |
| `[excited]` | 兴奋、激动 |
| `[neutral]` | 中性、平静 |
| `[fearful]` | 恐惧、害怕 |
| `[surprised]` | 惊讶、吃惊 |

其他标签（如 `[sleep]`、`[cute]`）也会以 `[标签]` 形式原样透传，不会导致调用失败。

## 频率限制

- `rate_limit_seconds` 设置调用间隔（秒），`0` 表示不限制
- 按 `event.unified_msg_origin` 区分用户，**管理员不受限制**
- 超过 120 秒未活动的记录自动清理

## 常见问题

- **语音发送不成功？** 确认消息平台支持语音组件（`Comp.Record`）。
- **没有反应？** 检查插件是否启用、API Key 是否正确、网络/代理是否连通、是否触发频率限制。
- **音频格式** 生成的是 WAV 格式临时文件，保存在插件对应临时目录，超过 24 小时的缓存文件会自动清理。
